# 미출현·궁합 연결 알고리즘

작성일: 2026-09-09
식별자: `overdue-chain-v1`

## 확정 규칙

1. 추천 대상 회차의 직전 회차까지 1회부터 전체 이력을 사용한다. 보너스는 제외한다. 기본 대상은 추첨 달력의 최신 발표 회차 다음이며 미수집이면 과거 자료로 대신 생성하지 않고 실패한다. 명시한 과거 대상도 지원하지만 미래 이력은 읽지 않는다.
2. 미출현 회차는 기준 회차 - 마지막 출현 회차다. 한 번도 나오지 않은 번호는 마지막 출현을 0으로 두므로 기준 회차만큼 미출현이다.
3. 45개를 미출현 내림차순·번호 오름차순으로 정렬해 10개씩 묶는다. 마지막 묶음은 5개다.
4. 각 묶음 안에서 출현 횟수 내림차순·번호 오름차순으로 정렬한다. 상위 5개를 각각 시작 번호로 사용한다. 중복으로 5조합을 채우지 못하면 6~10위, 이후 다음 묶음으로 진행한다.
5. 마지막 선택 번호의 궁합수를 전체 45개에서 조회한다. 이미 조합에 있는 번호는 건너뛴다. 동반 출현 내림차순 → 미출현 내림차순 → 전체 빈도 내림차순 → 번호 오름차순으로 하나를 고른다. 동반 이력이 없는 쌍도 0회로 순위에 포함한다.
6. 6개가 되면 저장할 번호만 오름차순으로 정렬한다. 순서가 달라도 같은 6개면 중복으로 버린다. 일부 번호가 겹치는 조합은 허용한다.
7. 서로 다른 5조합이 되면 즉시 반환한다. 조합 확장·랜덤 보충·이전 시작 번호 재시도는 하지 않는다. 방어적으로 전체 45개 소진 후 실패 처리한다.

## 종료 보장

- 무제한 while이나 재귀가 없다. 시작 번호는 최대 45개, 각 조합 확장은 정확히 5단계, 각 단계의 궁합 목록은 최대 44개다. 최악의 목록 검사 상한은 45×5×44=9,900번이다.
- 자기 자신을 뺀 후보 44개 중 사용 중인 번호는 최대 5개이므로 항상 다음 번호가 있다. 0회 동반 출현도 후보로 취급하기 때문에 빈 궁합 목록이 생기지 않는다.
- 각 결과는 시작 번호를 반드시 포함한다. 서로 다른 24개 시작 번호까지 결과가 4조합뿐일 수는 있지만, 25번째 시작 번호까지도 4조합뿐일 수는 없다(4조합이 포함할 수 있는 서로 다른 번호는 최대 24개). 따라서 현재 규칙과 정상 통계라면 최대 25번의 시작 번호 시도에서 5조합이 보장된다. 향후 추가 제외 조건이 생기면 이 보장은 다시 검토해야 한다.

## 비용과 재현성

- `winning_numbers`를 회차 인덱스로 범위를 제한해 한 번만 읽는다. 각 회차의 6개 번호와 15개 쌍을 집계한다.
- 45×45 동반 출현 행렬과 번호별 빈도·마지막 출현만 계산하고 45개의 궁합 목록을 한 번씩 정렬해 재사용한다. 814만 조합 생성이나 후보 테이블 적재가 필요하지 않다.
- 대략적인 비용은 이력 R회에 대해 O(15R + 45×44 log 44 + 9,900), 메모리는 이력 원본 O(R)와 고정 행렬 O(45²)다.
- 한 SELECT에서 읽은 동일 이력으로 통계를 계산한다. 별도 영구 캐시가 없어 당첨번호 정정 시 캐시 무효화 문제가 없다. metadata의 기준 회차·정규번호 지문·시작 번호 시도 목록·실제 연결 경로로 재현할 수 있다.
- 실행 UUID는 매번 달라도 번호는 동일하다. 동일 기준 반복 저장·제출을 새로운 번호로 간주하지 않는다. 이 알고리즘 자체에는 발급 회차 전체 중복 제외나 과거 1등 조합 제외를 추가하지 않았다. 외부 제출의 기존 중복 정책은 유지된다.

## 연동 범위

- 기존 `lotto:generate --algorithm=overdue-chain-v1`에서 생성·dry-run·명시 저장을 지원한다. 정확히 5게임만 허용한다.
- 제출 별칭은 `overdue`이며 `.env`의 `LUCKYDIVE_AI_OVERDUE_TOKEN`으로 전용 www 프로필을 인증한다. `lotto:submit --profile=overdue --dry-run`으로 확인하고 `--apply`로 제출한다. www 프로필 생성·실제 토큰 입력·자동 제출 스케줄은 수행하지 않았다.
- 실제 DB 변경이나 초기 통계 적재는 필요 없다. 확률 향상을 보장하는 알고리즘이 아니라 확정된 통계 순위 규칙으로 조합을 만드는 방식이다.

## 검증 결과

- 새 단위·기능 테스트 7개, 56개 검증 통과. generator 전체 45개 테스트, 3,592개 검증 통과.
- 궁합 동률의 각 우선순위, 마지막 선택 번호로 연결, 초기 10개 내부에서 빈도순 정렬, 중복으로 3번째 후보 묶음까지 이동하는 종료 경계를 검증했다.
- 메모리 DB에서 미리보기 무저장·명시 저장·과거 기준 재현·보너스 제외·누락 이력·미래 대상·수량 오류를 검증했다.
- 실제 로컬 이력의 1240회 기준 dry-run으로 1241회 대상 5조합을 확인했다. 시작 번호는 27, 45, 3, 17, 16이며 첫 후보 묶음에서 모두 확보했다. 실제 생성 원장 저장·외부 API 제출은 하지 않았다.
