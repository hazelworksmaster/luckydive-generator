# 미출현·궁합 연결 알고리즘

수정일: 2026-09-13
식별자: `overdue-chain-v1` / 생성 기록 규칙: `disjoint-games-v2`

## 확정 규칙

1. 추천 대상 직전 회차까지 1회부터 전체 당첨 이력을 사용하며 보너스는 제외한다. 기본 대상은 추첨 달력의 최신 발표 회차 다음이다. 누락 시 실패하며 과거 대상에는 미래 이력을 사용하지 않는다.
2. 미출현 기간은 기준 회차에서 마지막 출현 회차를 뺀 값이다. 한 번도 나오지 않은 번호는 마지막 출현을 0으로 둔다.
3. 전체 번호를 미출현 기간 내림차순, 출현 횟수 내림차순, 번호 오름차순으로 정렬한다. 미사용 번호 중 첫 번호를 게임의 시작 번호로 선택한다. 기존 10개 묶음과 묶음 내 빈도 우선 선정은 제거한다.
4. 마지막 선택 번호의 궁합수를 동반 출현 횟수, 미출현 기간, 전체 출현 횟수 내림차순과 번호 오름차순으로 조회한다. 현재 게임과 이미 완성한 게임에서 사용한 모든 번호를 제외하고 첫 후보를 선택한다. 동반 출현이 0회인 번호도 허용한다.
5. 6개까지 연결하고 표시할 번호는 오름차순으로 정렬한다. 실제 연결 순서는 기록에 보존한다.
6. 같은 방식으로 정확히 5게임을 만든다. 총 30개 번호는 모두 다르며 앞선 게임을 수정하거나 재시도하지 않는다.

## 종료와 비용

- 시작 번호 목록은 최대 45개를 검사하고 실제 게임 생성은 5번이다. 게임당 5단계, 단계당 최대 44개의 궁합 후보를 검사하므로 연결 검사 상한은 5×5×44=1,100번이다. 무제한 반복이나 재귀는 없다.
- 마지막 번호 선택 직전에도 사용 번호는 29개뿐이므로 미사용 번호가 16개 남는다. 궁합 0회도 허용하므로 정상 통계라면 항상 5게임을 완성한다.
- 이력 R회를 한 번 읽어 빈도·마지막 출현·동반 출현 행렬을 집계하고 45개의 궁합 목록을 한 번씩 정렬해 재사용한다. 후보 테이블이나 추가 migration은 없다.
- 시간 비용은 O(15R + 45×44 log 44 + 1,100), 메모리는 이력 O(R)와 고정 행렬 O(45²)다.

## 재현과 연동

- 동일 이력과 규칙이면 동일 결과다. 기준 회차·이력 지문·시작 번호 목록·연결 순서와 `selection_rule=disjoint-games-v2`를 기록한다. 과거 규칙 기록의 `candidate_batch`는 새 결과에 생성하지 않는다.
- 기존 `lotto:generate --algorithm=overdue-chain-v1 --dry-run`과 `lotto:submit --profile=overdue`를 유지한다. 생성 수량은 5게임만 허용한다. 토큰은 기존 `LUCKYDIVE_AI_OVERDUE_TOKEN`을 사용한다.
- 중복 제외 범위는 이번에 생성한 5게임이다. 다른 요청이나 과거 회차에서 사용한 번호까지 제외하지 않는다. 기존 제출 원장·재전송 본문·외부 제출 중복 정책은 변경하지 않는다.
- 이미 저장한 결과는 수정하지 않는다. 알고리즘 식별자는 호환을 위해 유지하며 새 규칙은 metadata로 구분한다. 예전 규칙 결과를 새 코드로 재계산하면 달라질 수 있다.
- 통계에 따른 번호 분산 방식이며 당첨 확률 향상을 보장하지 않는다.

## 검증 범위

- 5게임 전체 30개 번호의 유일성, 사용한 시작 번호 건너뛰기, 이전 게임의 궁합수 건너뛰기, 궁합 0회 보충과 유한 종료를 검증한다.
- 미출현 우선 시작, 시작 번호와 궁합 순위 동률 처리, 마지막 선택 번호 기준 연결과 재현성을 검증한다.
- 기능 테스트는 SQLite 메모리 DB에서 생성 명령·미저장·명시 저장·과거 이력 범위·보너스 제외·누락과 잘못된 요청을 검증한다.
