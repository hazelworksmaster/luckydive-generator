# 추천번호 공통 생성 규칙

적용일: 2026-10-02

## 직전 게임 중복 제한

- 이번에 생성하는 게임 순서를 기준으로 바로 직전의 확정 게임과만 비교한다. 같은 번호는 최대 2개까지 허용하고 3개 이상이면 후보를 제외한다.
- 첫 게임은 비교 대상이 없다. 다른 생성 요청이나 이전 제출의 마지막 게임을 읽지 않는다.
- 더 앞선 게임과 일부 번호가 3개 이상 겹치는 것은 이 규칙으로 제한하지 않는다. 기존의 완전히 같은 6개 조합 중복 제외는 별도 규칙으로 유지한다.
- 공통 구현은 `PreviousGameOverlap`이며 현재 `random-v1`·`filtered-v1`·`weighted-v2`·`overdue-chain-v1`·`frequent-spread-v1` 모두에 적용한다.

## 랜덤 적용

- 암호학적 난수로 1~45에서 서로 다른 6개를 추출하고 정렬한다. 동일 조합 또는 직전 게임과 3개 이상 겹친 후보는 버린 뒤 다시 추출한다.
- 거부한 후보는 직전 게임이나 확정 조합 집합에 넣지 않는다. 무작위 후보를 검증해 채택하므로 허용된 후보 사이에 임의의 우선순위를 두지 않는다.
- 한 요청당 후보 검사 상한은 10,000번이며 초과하면 실패한다. 부분 결과를 반환하거나 저장하지 않는다.
- 기존 `random-v1` 식별자·명령·random 제출 프로필을 유지한다. 과거 저장 결과나 재전송 본문은 변경하지 않는다. migration은 필요 없다.
- 단위 테스트로 첫 게임, 중복 0~6개 경계, 직전 게임만 비교하는 사례를 검증한다. 통합 테스트로 100게임의 인접 중복 제한과 기존 저장·미저장 경로를 검증한다.

## 필터드 적용

- 기존 filter1~filter6 계산과 후보 테이블은 유지하고 filter6에서 뽑은 후보에 공통 규칙을 적용한다. 후보를 재준비하거나 migration할 필요는 없다.
- 연속 ID를 균등 난수로 추출해 최대 100개씩 묶어서 조회하고 난수 추출 순서대로 검사한다. 직전 확정 게임과 3개 이상 겹친 후보는 건너뛴다. 다음 게임에서는 같은 후보를 다시 검토할 수 있다.
- 이미 선택한 후보 ID는 재사용하지 않는다. 비교 대상은 마지막 확정 게임이며 후보를 거부해도 비교 대상이 바뀌지 않는다.
- 한 요청당 난수 추출은 최대 10,000번, 후보 조회는 최대 100번이다. 조건을 채우지 못하면 예외로 종료하며 조건 완화·부분 결과 저장·후보 소비는 하지 않는다. 유효한 순서가 있어도 무작위 선택 경로에 따라 실패할 수 있으며 다시 실행할 수 있다.
- 필터 준비 상태 잠금과 기준 이력 검증은 유지한다. 실제 운영 DB 변경이나 API 제출은 실행하지 않는다.

## 가중치 적용

- weighted-v2의 모델 계산과 준비 후보는 그대로 유지한다. 생성 단계에서 기존 난수 시작 순번 이후 탐색·끝에서 처음으로 돌아가는 선택에 공통 중복 검사를 추가한다.
- 직전 게임과 3개 이상 겹치면 이번 게임의 탐색에서만 제외한다. 다음 게임에서는 다시 검토할 수 있다. 확정 후보와 과거 당첨 조합 제외는 요청 전체에서 유지한다.
- 기존 회차 전체의 동일 조합 발급 제외는 유지하고 새 중복 제한은 이번 요청의 직전 게임만 비교한다. 이전 요청의 마지막 게임까지 비교하지 않는다.
- 후보 소진 또는 요청당 10,000번의 탐색 제한 도달 시 실패한다. 미리보기는 소비하지 않고 저장 시 확정 후보만 발급 원장과 함께 transaction으로 기록한다. 실패 시 부분 저장은 없다.
- 후보 재준비나 migration은 필요 없으며 서비스 제출도 같은 생성 경로를 사용한다. 이미 저장된 재전송 본문은 변경하지 않는다.

## 미출현 적용

- 전체 게임의 번호 재사용 금지를 제거하고 미출현 순으로 시작 번호를 한 번씩 검토한다. 앞선 게임의 연결 번호도 이후 시작 번호나 궁합수로 사용할 수 있다.
- 궁합 순위와 동률 처리는 유지한다. 연결할 번호를 하나씩 추가할 때 공통 규칙으로 직전 게임과의 중복이 2개를 넘지 않는지 검사한다. 이미 현재 게임에 있는 번호는 제외한다.
- 더 앞선 게임과 일부 중복은 허용하되 완전히 동일한 6개 조합이면 다음 시작 번호를 검토한다. 최대 45개 시작 번호 × 5단계 × 44개 후보로 유한하게 종료하며 조합을 채우지 못하면 실패한다.
- 기록의 selection_rule은 `previous-overlap-v3`으로 구분하고 기존 `overdue-chain-v1`·`overdue` 명령과 토큰은 유지한다. 과거 저장 결과와 재전송 본문은 그대로 유지한다.

## 자주 나온 번호 분산 적용

- 출현 상위 5개의 시작 번호 예약과 낮은 동반 출현 순위는 유지한다. 시작 번호는 각 게임 전용이고 다른 게임의 연결 번호로 사용하지 않는다.
- 연결 번호의 전체 게임 재사용 금지를 제거한다. 게임별 사용 집합을 초기화하고 번호를 추가할 때 공통 규칙으로 직전 확정 게임과 최대 2개 중복인지 확인한다.
- 더 앞선 게임과 3개 이상 중복은 허용한다. 각 게임은 다른 게임에 없는 전용 시작 번호를 포함하므로 동일한 6개 조합은 나오지 않는다.
- 최대 5게임 × 5단계 × 44개 후보를 검사한다. 시작 번호 예약과 직전 게임 번호를 제외해도 충분한 후보가 남으므로 추가 준비 없이 완료한다.
- selection_rule은 `previous-overlap-v2`로 기록하며 명령 식별자·프로필·토큰은 유지한다. 과거 저장 결과나 재전송 본문은 변경하지 않는다.
