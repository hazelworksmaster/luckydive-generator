# 자주 나온 번호 분산 생성기

식별자: `frequent-spread-v1`

## 규칙

1. 추천 대상 직전 회차까지 1회부터의 정규 당첨번호를 사용하고 보너스를 제외한다. 누락 이력은 실패한다.
2. 전체 출현 횟수 내림차순, 작은 번호 순서로 상위 5개를 선택해 각 게임의 시작 번호로 예약한다.
3. 마지막 선택 번호와 동반 출현 횟수가 적은 순서로 연결한다. 동률은 전체 출현 횟수가 적은 번호, 작은 번호 순서다. 동반 출현 0회도 허용한다.
4. 예약한 모든 시작 번호와 현재·이전 게임에서 사용한 번호를 연결 후보에서 제외한다.
5. 시작 번호 순서대로 게임당 6개를 채워 5게임을 만든다. 결과는 게임별 오름차순, metadata에는 시작 번호·연결 순서·기준 회차·이력 지문·규칙을 기록한다.
6. 중복 제외 범위는 한 번 생성하는 5게임이다. 동일 이력이면 같은 결과를 생성하며 기존 저장·제출 이력의 번호까지 제외하지 않는다.

## 종료와 효율

- 이력 검증과 빈도·궁합 집계는 미출현 생성기와 공용으로 사용한다. DB는 범위 SELECT 한 번이며 별도 후보 테이블이나 migration은 필요 없다.
- 시작 번호 5개를 예약하고 25개를 추가한다. 마지막 추가 직전에도 16개가 남으므로 정상 통계라면 항상 완성한다.
- 게임 5개 × 추가 5단계 × 후보 최대 44개로 연결 검사는 최대 1,100번이다. 재귀나 무제한 재시도는 없다.
- 각 번호의 궁합 순위는 한 번 정렬해 재사용한다. 시간 비용은 이력 R회 기준 O(15R + 45×44 log 44 + 1,100)이다.

## 사용과 검증

- `php artisan lotto:generate --algorithm=frequent-spread-v1 --dry-run`으로 저장 없이 생성한다.
- `--draw-no`는 2회부터 최신 발표 다음 회차까지 지원한다. `--count`는 5만 허용한다. `--save`는 생성기 원장 저장이다.
- 제출 별칭은 `frequent`, 토큰 환경 변수는 `LUCKYDIVE_AI_FREQUENT_TOKEN`이다. 기존 BASE URL과 토큰 인증 context로 서비스 프로필 UUID를 확인한다. `lotto:submit --profile=frequent --dry-run`은 전송 계획을 확인하고 `--apply`는 생성·저장·제출한다. dry-run의 context 조회도 서비스 토큰 사용 시각을 갱신할 수 있다. 실제 토큰·서비스 프로필 생성·스케줄은 별도 운영 작업이며 새 이미지 배포가 필요하다.
- SQLite 메모리 DB 테스트로 명령 선택·저장·재현·미래 이력 및 보너스 제외·누락 이력을 검증한다. 단위 테스트로 시작 번호 예약, 30개 유일성, 동률 우선순위와 마지막 번호 연결을 검증한다.
- 통계에 따른 선택 규칙이며 당첨 확률 향상을 보장하지 않는다.
