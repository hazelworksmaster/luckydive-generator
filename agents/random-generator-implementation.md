# 랜덤 생성기 구현 기록

정리일: 2026-09-08

## 구현

- 전체 8,145,060개 조합에서 균등 추출하는 `random-v1`을 구현했다. 전체 조합 적재는 필요하지 않다.
- 1~100게임, 기본 5게임이다. 한 게임은 1~45 중 서로 다른 정수 6개이며 한 실행 안의 게임 중복을 제거한다.
- 과거 당첨번호 제외·가중치·실행 간 중복 제거는 적용하지 않는다.
- `lotto:generate`는 기본 미저장, `--dry-run`은 명시적 미저장, `--save`는 생성 원장 저장이다.
- 생성기 전용 `recommendation_runs` migration을 준비했다. API 제출·재시도·스케줄러는 미구현이다.

## 실제 DB 점검

- 설정된 local 환경의 DB 접근에서 MySQL 오류 1044가 발생했다. 계정의 대상 DB 접근 권한 확인을 사용자에게 요청했다.
- 최초에는 테이블 목록·기존 건수를 읽지 못해 migration을 보류했다. 이후 권한 수정과 사용자 실행 확인을 거쳐 아래와 같이 적용했다.
- 권한 해결 후 읽기 전용 재점검에서 대상 개발 DB의 기존 테이블이 0개임을 확인하고 실행 직전 사용자 확인을 받았다.
- 예정 변경은 Laravel migration 관리 테이블(없는 경우) 및 `recommendation_runs` 생성이다. 생성 원장에는 자동 초기 데이터를 넣지 않는다.
- 빈 테이블 생성은 되돌릴 수 있지만 저장 결과가 생긴 뒤 rollback하면 소실되므로 백업을 선행한다.

## 검증

- SQLite `:memory:` 테스트 5개, 단언 3,321개 통과.
- 게임 범위·정렬·게임 내외 중복, 미저장·저장, 잘못된 입력을 검증했다.
- 실제 CLI `--count=5 --dry-run` 성공 및 `saved: false` 확인.
- PHP Pint 포맷 정리 완료. 커밋과 외부 API 제출은 하지 않았다.


## Migration 적용 완료

- 2026-09-08 사용자 `진행해줘` 확인 후 개발 DB `luckydive_generator_dev`에 `php artisan migrate --force --no-interaction`을 실행했다.
- `migrations` 및 `recommendation_runs` 생성 성공. `migrate:status`에서 해당 migration의 배치 1, Ran 상태를 확인했다.
- 읽기 전용 재조회로 동일 DB와 두 테이블을 확인했다. 새 추천번호 생성·저장·외부 API 제출은 실행하지 않았다.
- 기존 데이터가 없는 상태에서 스키마만 생성했으며, 이후 생성 결과를 저장한 상태의 rollback은 데이터 소실을 수반하므로 별도 점검·백업·확인이 필요하다.


## 알고리즘 선택 확장

- `lotto:generate --algorithm=random-v1` 옵션 및 설정 기반 생성기 등록 목록을 추가했다.
- 옵션 생략은 설정의 기본 알고리즘을 사용하고 알 수 없는 값은 실패한다. 요청 이름을 클래스명으로 직접 실행하지 않는다.
- 구현 계약과 버전 식별자를 검증하며 실제 선택한 버전을 생성 결과와 원장에 기록한다.
- 실제 DB 변경과 외부 API 제출은 필요하지 않은 코드 확장이다.
